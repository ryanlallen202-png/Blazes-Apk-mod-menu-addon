## Findings in the pinned compiled source

1. **Stereo upload offset:** SetData receives `g_soundLoadOffset * g_soundLoadChannels`. The position is a frame offset, not an interleaved float index. At the second stereo chunk, 4096 should be passed, not 8192. This can fail or wrap/overwrite audio depending on clip length.
2. **Legacy voice compatibility:** routing requires `get_IsRecording`; no `RecordingEnabled` compatibility path exists. This is the same missing capability observed in the earlier supplied device log. This audit does not assume the current headset has that exact API.
3. **Restoration failure:** the override flag is cleared before restore setters execute, and the saved references are cleared even when a setter throws. The current branch's fault-injection tests cover retained snapshots and bounded retries instead.
4. **GC replacement ordering:** the pinned Ref frees the old root before rooting the replacement. An executable probe using the actual extracted Ref and a simulated collection window reproduces loss during `ref.set(ref.get())`. This is a host simulation, not an observed headset collection.
5. **Native audio invocation/handoff:** the pinned source still uses direct audio calls and immediate post-upload playback setup rather than the current guarded invoker and staged handoff. The exact runtime consequences require a device test; compilation alone does not validate them.

These fixes already existed in the combined branch. They are not present in the user-linked artifact.

## Additional regression found and fixed during this pass

float arrays, native uploads and GC retention. When retaining a newly created clip
failed, the implementation returned with decoded state still active and retried
native clip creation on the next frame. The new assertion failed before the fix.

**Verified Combined 13** stops the load after failed retention and attempts cleanup
of that one clip rather than repeatedly allocating more. The assertion now passes.
